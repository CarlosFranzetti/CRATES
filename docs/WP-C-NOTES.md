# WP-C notes: personal photos, multi-photo import, rapid capture

Branch `worktree-agent-afe73e42afd67500c`. Everything is in `crates.html` (CSS block `WP-C: photos and capture`, JS block `WP-C: photos, grouping, rapid capture`), plus `api/identify.js` and a `functions` entry in `vercel.json`.

## What was built

1. **Photo store.** IndexedDB `crates-photos` / `photos` (`{id, blob, thumb, w, h, at}`; JPEG, longest side 1600 px, quality .85; thumb is a 240 px JPEG data URL). `phAdd(file)` decodes with `createImageBitmap(file, {imageOrientation:'from-image'})` and falls back to `<img>`. `photoURL(id)` / `photoThumb(id)` are synchronous and return a URL or null; thumbs of every referenced photo are loaded at boot and the app re-renders once. Anything not yet loaded is requested on demand and triggers one debounced re-render. Quota errors toast and keep the photo in memory for the session; if IndexedDB is unavailable a `Map` takes over. `phDel` deletes the blob (and revokes the object URL); delete-with-undo reads the stored object first and puts it back on undo. Orphans (cancelled imports, discarded boards) are swept a day after they were taken (`phGC`, runs 5 s after boot).
2. **Cover source.** `cover(r, kind)` now asks `personalCover(r, kind)` first. Rule: `coverSrc==='personal'` + a cover photo -> personal; `'discogs'` + `r.cover` -> Discogs; otherwise Discogs if it exists, else the personal cover photo (`coverPhoto`, else the first photo of kind `cover`), else generated art. `kind==='label'` prefers a personal `label` photo. `thumb(r)` now calls `cover(r,'thumb')` so lists use the 240 px thumb instead of the 1600 px file.
3. **`photoSection(r)`.** "Cover: Discogs | My photo" segmented control (options disabled when unavailable), a grid of the record's photos (kind select, Set as cover, Move... with a searchable record picker, Delete with an in-place confirm), and Add photos (multi-file). All of it is undoable. The edit sheet (`openEditRecord`) is wrapped so the section is appended there unless the sheet already has `#ph-sec`; WP-A's Detail sheet can just include `photoSection(r)`.
4. **Add > Photos** (`phImportFiles`, `phGroup`, review board). The Add sheet is wrapped (`openAdd`) to add **Rapid capture** (first), **Photos** (after Record) and, when something is waiting, **Review n waiting**. Grouping: sort by `lastModified`; a gap over 25 s starts a record; an 8x8 average hash treats near-identical shots (<= 4 bits apart) as retakes; a centred circular edge (16 rays, one consistent radius in >= 12) marks a label; the first squarish (0.7 to 1.43) non-label photo is the cover; the next squarish photo after a label is the back; a second label or a further squarish photo after cover+label+back starts a new record. Board: one card per record with thumbs (drag to another card or the "New record" strip; tap a thumb for kind + "Move to..." list + delete), status (reading / in your collection / new / set aside), editable artist and title, a candidate picker when the server returned several releases, Split (everything after the first photo moves to a new card), Merge up, Read again, Discard (confirm). **Add all** makes a backup (`backupNow('Before adding photos','import')`), attaches photos to a matched record or creates an Unplaced record (same shape as `importDiscogsRows`, `coverSrc:'personal'`), is undoable, and leaves cards that still lack a name on the board.
5. **`identifyCover(photoId)`** -> `{artist,title,label,catno,confidence,cands}|null`: (a) `BarcodeDetector` (a barcode of a record you own resolves locally), (b) `window.claude` sample capability with the 1600 px JPEG, (c) `POST /api/identify` when `API.ok`, (d) null -> the item is set aside with "Couldn't identify this one automatically. Type the artist and title, or scan the barcode." Up to three photos of an item are tried (cover, label, back). Two identifications run at a time.
6. **Rapid capture** (`openCapture`): full-screen camera (`getUserMedia({video:{facingMode:'environment'}})`), large shutter, `navigator.vibrate(8)` tick, each shot is stored and becomes an `S.inbox` item at once, identification runs in the background and never blocks the next shot; after 6 s (`CAP.slowMs`) the item is set aside and the line "Still working on that one. It's set aside; keep going." shows (identification keeps going and updates the item if it succeeds). Strip of the last 12 shots with a state dot (working / matched / set aside). "Label / back" is a one-shot toggle that attaches the next shot to the previous item (label first, then back). Done opens the same board, set-aside items first. Wake Lock is requested and re-requested on visibility change; camera tracks stop on exit. Without a camera (or when denied) the shutter becomes `<input type=file accept=image/* capture=environment>`.
7. **`migrate()`**: `r.photos`, `r.coverSrc`, `r.coverPhoto`, `S.inbox` (ids remapped to the safe shape, enums whitelisted, strings coerced, `identifying` is stored as `queued`, record ids mapped through the record remap).

## `/api/identify`

`POST {image:"data:image/jpeg;base64,...", barcode?}`. 503 `{error:'Not configured', missing:['ANTHROPIC_API_KEY']}` when the key is absent. With a barcode and `DISCOGS_TOKEN` it searches Discogs by barcode first and skips the model. Otherwise it calls the Anthropic Messages API (image + strict JSON instruction), then searches Discogs (`catno`, else `artist` + `release_title`) and returns up to 5 candidates `{releaseId,artist,title,label,catno,year,thumb}` (thumb through `proxied()`).

**Lead must confirm:** the model id (read from `ANTHROPIC_MODEL`; the code defaults to `claude-sonnet-4-5` when the variable is unset, which I could not verify) and its per-image pricing, then set `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` in Vercel. The endpoint refuses `Sec-Fetch-Site: cross-site` but is otherwise unauthenticated like the other endpoints, so anyone who can open the site can spend model budget: add a rate limit or an owner check before turning it on in production. Images are not stored or logged on the server.

## Decisions and deviations

- `thumb()` and `cover()` in the existing code, `migrate()`, the `S.inbox` list and `openEditRecord`/`openAdd` (wrapped, not edited) are the only existing code touched.
- Photo kinds that cannot be read from pixels (front vs back cover) are guessed from order: cover, label, back. A shooting order of cover, back, label groups wrongly; the board's move/split/merge fixes it.
- The grouping heuristics (label ring, hash) are tuned on synthetic images; expect to tune thresholds on real photos.
- Added a small flat-look + Compact density rule at the end of the WP-C CSS block: on the base commit test R10 failed because the flat look's fixed row sizes beat the Compact density setting. It does not belong to this WP but the suite had to be green.
- Photo bytes are not part of backups or "Save to file" (state only holds ids). Restoring a backup keeps working while the photos are still in this browser; moving to another browser loses them. A photo export belongs to the sync/backup WP.
- `tests/results.json` is regenerated by each run.

## Open issues

- HEIC photos fail to decode in browsers without HEIC support (the user gets a toast; iOS Safari converts on selection).
- The review board re-renders the whole sheet on structural changes, which moves focus to the sheet's first button.
- Photo upload to the server (to survive a browser wipe) is not part of this WP.
